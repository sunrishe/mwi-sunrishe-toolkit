# 食用工具 ↔ MST 市场数据桥接

供「[银河奶牛]食用工具」（GreasyFork 脚本 499963，作者 Truth_Light）使用的市场订单数据桥接脚本，解决两件事：

1. **食用工具 ↔ MST**：MST 的市场交易记录只读自己的油猴存储，而油猴的 GM 存储按脚本隔离——本脚本通过在食用工具里 `@require` 引入，运行在食用工具的沙箱中，从而可以直接读写它的 `market_list`，把历史订单迁移到 MST，或把 MST 的记录导回食用工具。
2. **食用工具 ↔ 食用工具**：同一份导出文件在另一台设备（或另一个浏览器、另一个油猴安装）的食用工具里导入，支持合并与覆盖。

**导出与导入只有一种格式**：MST 的市场交易记录格式（`{app:'MST', type:'market-history', …}`）。导出时把食用工具的 `market_list` 转成该格式，导入时再转换回食用工具条目，因此同一份文件既能给 MST 用，也能在食用工具之间迁移。

## 文件

- `edible-tools-market-bridge.js`：桥接脚本本体，不要安装为独立脚本，用 `@require` 引入食用工具。

## 接入方式

1. 打开食用工具的脚本编辑页，在脚本头（`// ==UserScript==` 块内）加一行：

   ```javascript
   // @require file:///你的路径/edible-tools-market-bridge.js
   ```

   - 本地文件需要油猴开启「允许访问文件网址」（Tampermonkey 设置 → 通用 → 配置模式/安全，视版本而定）；也可以把本文件放到可访问的 https 地址后写 URL。
   - 修改的是你本地那份食用工具，脚本更新后需要重新加这一行。

2. 保存并刷新游戏页面，打开食用工具设置面板 → **银河奶牛数据库 → 市场数据**，在「仅保留已完成订单」按钮后面会出现两个新按钮。

## 两个按钮做什么

| 按钮                | 行为                                                                                                                                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 导出到 MST 交易记录 | 读取食用工具的 `market_list`，转换成 MST 的市场交易记录格式（`MWI_Market_History_from_Edible_Tools_<时间>.json`，紧凑单行）并下载。MST 侧用它「导入」；另一台设备的食用工具用它「导入到食用工具」也能恢复或合并。 |
| 导入到食用工具      | 选择上面那份 MST 格式 JSON，自动转换成食用工具条目后询问导入方式，再写回食用工具的 `market_list`。                                                                                                                |

导入写回的条目与食用工具自身的条目结构一致（官方挂牌对象 + `lastUpdated`），不追加任何自定义字段；因此 MST 的「环境」与「订单类型」在条目里没有落点，再导出到 MST 时环境按所在页面判定、类型统一按挂牌处理。

按钮文案跟随食用工具界面语言（与它自身一致：读游戏的 `localStorage.i18nextLng`，非 `en` 即中文）。

## 导入方式（prompt 选择）

点「导入到食用工具」选好文件后，会弹出 prompt 让你选择：

```
请选择导入方式（输入 1 或 2）：
1 = 合并：同一订单按状态与更新时间合并，新订单追加（现有 N 条 + 文件 M 条）
2 = 覆盖：先清空现有 N 条，再写入文件里的 M 条
```

- 输入 `1`（或 `merge`）= **合并**：同一订单 id 按下述规则合并成一条，文件里的新订单追加到现有数据后面。
  - 终态优先：`filled` / `cancelled` / `expired` 胜过 `active`（设备 A 只看到「进行中」、设备 B 看到「已完成」时，合并结果是「已完成」）；
  - 两边同状态时取 `lastUpdated` 较新的一条；时间相同或缺失时以导入的文件为准；
  - 已成交数量、挂牌数量、税费取两者较大值；创建/过期时间取存在的值；`lastUpdated` 取较新。
- 输入 `2`（或 `overwrite`）= **覆盖**：先清空现有数据再写入文件内容，**会有一次 confirm 二次确认**（提示会清空 N 条）。清空的是整个 `market_list`（含其它角色的条目），与 MST 侧「覆盖只替换文件涉及的分桶」不同。
- 直接取消 prompt、或连续三次输入非法内容，则放弃导入（不改动任何数据）。

## 字段与口径

食用工具的 `market_list` 存的就是官方挂牌对象原文（对照食用工具 v0.514 源码核对：收到官方数据时按 `id` 整条替换，另加它自己维护的 `lastUpdated`），两边字段一一对应：

| 食用工具条目字段                                                               | MST 记录字段                                           | 说明                                                                                                                     |
| ------------------------------------------------------------------------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `id`                                                                           | `key` = `listing:<id>`、`listingId`                    | 官方订单 id，合并与去重的主键                                                                                            |
| `characterID`                                                                  | `characterId`                                          | 导出到 MST 时按「环境 + 角色」分桶（正式服/测试服按当前域名判定）；个别条目缺该字段时用当前页面的 `characterId` 参数兜底 |
| `status`（`/market_listing_status/*`）                                         | `status`（active/filled/cancelled/expired）            | 状态 hrid 与短值互转                                                                                                     |
| `isSell`                                                                       | `side`                                                 | 出售/收购                                                                                                                |
| `itemHrid` / `enhancementLevel` / `price` / `orderQuantity` / `filledQuantity` | 同名字段                                               | 数量与价格口径一致                                                                                                       |
| `createdTimestamp`                                                             | `createdAt`                                            | 官方创建时间（纳秒 ISO，截断到毫秒）；条目缺该字段时用 `lastUpdated` 兜底并标「推断时间」                                |
| `expirationTimestamp`                                                          | `expiresAt`                                            | 官方过期时间                                                                                                             |
| `taxTaken`                                                                     | `taxTaken`                                             | 本单累计税费                                                                                                             |
| `unclaimedCoinCount` / `unclaimedItemCount`                                    | 同名字段                                               | 待领取金币/物品                                                                                                          |
| `lastUpdated`（食用工具自己加的）                                              | `updatedAt`；已成交/取消/过期时同时作为完成时间        | 食用工具只记「最后更新时间」，没有独立的成交时间；有成交时同时用它近似首次成交时间                                       |
| —                                                                              | `collectedCoinCount` / `collectedItemCount` / `claims` | 食用工具没有记录领取，导入 MST 时按 0 / 空处理；MST 会对这类记录按成交当时的市场税率推算实际到账并标注（推算只写在 MST） |

## 注意

- **直购/直售的两种去向**：MST 里没有官方订单 id 的「立即购买/立即出售」兜底记录无法表达成食用工具的条目，导入食用工具时会跳过并在提示里报数（实测确认直购不产生服务端条目，见 MST 需求说明书 §4.5）；有官方订单 id 的直购记录可以往来，但食用工具条目没有「直购」概念，再导入 MST 时按挂牌记录记入。
- **实际到账由 MST 推算**：食用工具没有领取记录，导入 MST 后「实际到账」会按成交当时的市场税率推算并标注；只有 MST 自己观测到的官方到账数据才是权威值。
- **食用工具的存储不区分正式服/测试服**：`market_list` 是同一份，条目里也没有环境字段；导出到 MST 时统一按导出时所在页面判定环境，跨环境使用时请分开导出。
- **覆盖模式不可撤销**：导入前先点「导出到 MST 交易记录」留一份，该文件本身就能导回来；覆盖会清空整个 `market_list`，包括其它角色的条目。
- 只处理市场订单数据，不读取食用工具的开箱/公会/战斗等其他数据。
