## 当前状态：v2.17.1 WebSocket 页面桥改为透明转发（2026-09-24）

### WebSocket 页面桥适配其它脚本

- 目标：工具箱的采集始终有效，同时不再成为其它脚本的失效来源；其它脚本之间互相造成的原型链断裂不归本桥处理，只保证自身既不失效、也不新增失效。
- 根因：旧实现用普通函数替换构造器，靠 `IntegratedWebSocket.prototype = OriginalWebSocket.prototype` 借用原生原型，而函数体内的 `new OriginalWebSocket(...)` 会丢弃 `new.target`。后装脚本在此基础上再 `class extends`（`Oi momomo 公会试炼助手`）时，派生类原型不在真实实例链上：打在 `window.WebSocket.prototype` 上的补丁（`MWI 战斗工具` 加载时读取 `WS.prototype.addEventListener` 与 `onmessage` 描述符）失效，`socket instanceof WebSocket` 变 `false`。
- 改法：`data.js` 的 `createWebSocketService` 注入源码改为 `new Proxy(OriginalWebSocket, {construct})` 只做转发，`Reflect.construct(target, args, newTarget)` 把 `new.target` 原样交给下层构造器，实例原型完全由下层构造器决定；`instrument(ws, url)`（`isGameWs` 过滤、`send` 包装、message/open/close 监听）逐行保持原样，仅换了挂载位置。删除 `IntegratedWebSocket.prototype = ...`、四个静态常量拷贝与 `window.WebSocket = IntegratedWebSocket`；哨兵 `window.__mwiIntegratedWsInstalled`、三个 `mst:ws:*` 事件名、`handleMessage` 分发与 `PageBridgeService.install` 调用方式不变。
- 边界（有意不覆盖）：`主站一键导入`(8) + `Oi`(17) + `战斗工具`(25) 这类"函数式包装在内、class 继承在外"的组合在工具箱缺席时同样失效，桥不做 `setPrototypeOf` 对齐去替它们修复；把 `window.WebSocket` 整体换成不调用前一个构造器的假对象也需访问器拦截，默认不做。长期规则见 `docs/业务功能要求.md` §三「WebSocket 页面桥」。
- 测试：`tests/core-regression.test.js` 的 WebSocket 断言新增 `new Proxy(OriginalWebSocket`、`Reflect.construct(target, args, newTarget)` 正向匹配与 `IntegratedWebSocket.prototype`、`setPrototypeOf` 反向匹配，锁定"只转发、不改原型"。

## 2.17.0 订阅通知任务开始通知、提醒可信度与地下城牛铃收益选项（2026-09-23）

### 订阅通知任务开始通知

- 新增第四个消息类型复选框「任务开始」（`notifyStart`，默认开启，旧配置缺字段视为开启）；消息类型行顺序为 **任务开始 → 任务完成 → 队列为空 → 定期进度**（模板顺序即渲染顺序，复选框 id 与悬浮说明随标签一起移动）。窄屏下该行 `flex-wrap: wrap` 折行，四个选项不会挤出弹窗。
- 触发口径：**队首换成另一个任务即推送**——完成切换（`type='completed'`）、被其他任务顶掉、被挤下去的任务重新回到队首、有限任务未达上限被移除的取消切换、空队列入队（后三类 `type='started'`）都算。`started` 的 `completedTask` 固定为 `null`（取消不算完成）；无上限行动出队仍按 `completed` 上报（与已完成无法区分取消）。同一 `id` 返回 null，因此迷宫在队首连续跑不同环节、战斗连续打不同波次都不触发事件。
- 组队战斗由开战播报：`handlePartyUpdated` 读取 `partyInfo.party.status`，进入 `battling` 时播报任务开始（`notifyPartyBattleStart`，要求队首 `partyID !== 0`）；`isPartyStartDeferred`（`partyID !== 0 && partyStatusKnown`）让队首变化那条规则对组队/战斗行动不再播报，避免入队与开战各报一条内容重复的通知。依据是"是否拿到过队伍状态"：拿不到 `partyInfo.party.status` 时退回队首变化播报，保证不至于一条都收不到。游戏源码依据 `main.bdda2571.chunk.js`：`PartyStatus` 为 creating/recruiting/battling/disbanded，官方 `handleMessagePartyUpdated` 在 `"battling" !== n && "battling" === r` 时自己发 `sendPartyStartedNotification`，即"准备就绪并过了等待期"的官方信号；战斗结束退出 `battling`，下一轮再进入再推一条。基线（`init_character_data`）里正在开战只记录不推送。
- 消息内容：一次队首变化只提交一条 `buildQueueChangeText(event, {complete, start})`——标题行 + `✅ 完成：<任务>`（可关）+ `▶️ 开始：<任务>`（可关）+ `等待队列：` 概览（与进度通知同口径：不含队首、最多 3 项、超出以 `…共 N 项` 收尾）+ 腾空提醒 + 时间行 + 角色名行；`handleEvent` 先算 `complete` / `start` 两个开关布尔量，都关则不推送。组队开战播报走同一构造器（只传 `newTask`，`{complete: false, start: true}`）。
- 队列概览只有「等待队列」一段：已执行过、轮到会接着做下去的任务由非零次数直接体现（如 `伐木（12/100）`），不另列「继续执行」段。口径为 `getWaitingQueuePreview`（不含队首、最多 3 项）与 `getWaitingQueueLength`（计全部等待任务），完成、开始、进度三类通知共用。
- 行动名按官方 `getActionDisplayName` 组装（`actionName(task)` + `primaryItem(task)`）：炼金类（`/action_functions/alchemy`）显示「行动名: 物品名」、强化（`/action_functions/enhancing`）只显示「物品名」，物品强化等级 ≥ 1 时追加 ` +N`；行动 `function` 从 `DataHub.getClientDataMap('actionDetailMap')` 取，物品 hrid 从 `CharacterAction.primaryItemHash` 按官方 `computeItemFromHash` 的 `::` 分隔格式切分（`characterId::itemLocationHrid::itemHrid::enhancementLevel`），物品名走 `getLocalizedGameName('itemNames', hrid)`；解析不到物品时退回行动名（不显示原始哈希，也不显示官方的 `actionsUtil.itemNotAvailable`）。采集/制作类的 `actionHrid` 本身按物品命名，行为不变。
- 默认最小推送间隔 5 秒：`createDefaultConfig().minIntervalSec = 5`，`ensureSender` 的兜底值同步为 5（范围仍为 5–600）；已保存的配置不受影响，需在设置弹窗里自行调整。5 秒仍低于钉钉/企微约 20 条每分钟的官方限流。

### 订阅通知提醒可信度

- 队列为空提醒要求已经拿到过全量基线：`QueueChangeTracker.hasBaseline` 只在 `setQueue`（`init_character_data` 全量快照）后为真，增量消息不构成基线，`reset` 清除。未拿到基线时队列为空只代表“没有数据”，不推送提醒——未登录或在掉线状态打开的页面既收不到 `close` 事件也收不到基线，没有这条前置会每分钟误推一条“行动队列已空”。完成通知不受此限制（事件本身来自游戏消息）。
- 在线状态默认未确认：`wsConnected` 初值为 `false`，必须由 WS `open` 或 `init_character_data` 确认，未确认前不跑定时推送。
- 队列跟踪常驻：`onWsMessage` 不再按订阅开关早退，订阅关闭期间照常合并官方增量维护基线（只跟踪不推送、不补推），推送判断下移到 `handleEvent` 内部；`toggleEnabled(true)` 调用 `markTaskActivity()` 重置进度与空队列计时，重新开启后按当前队列继续，不会按关闭前的旧计时立刻补推一条。
- 掉线判定收敛到一处 `isSessionTrustworthy(now)`，定时推送三条同时成立才跑，任一不满足即暂停、恢复（页头回来或重连基线重建）后自动继续：① **页面判据（主）**——`isHeaderPresent()` → `GameUiAdapter.query('headerCharacterInfo')` 取不到即按掉线处理；实测断线页面 `[class*="Header_characterInfo"]` 与 `[class*="FullAvatar_"]` 数量均为 0、页头外壳 `[class*="Header_header__"]` 仍为 1，所以判据只能用角色信息块/头像，**不能用页头容器**（断线时游戏把整块游戏 UI 换成连接提示面板，见游戏源码 render 分支）；② 没有观测到 WS `close`（被挤掉/断网时游戏立刻断开重连，事件比 UI 更早）；③ 会话未长期静默——`lastMessageAt` 与 `SESSION_SILENT_MS = 11 * 60 * 1000`，依据游戏源码 `setInterval(this.sendPing, 6e5)` 的 10 分钟 ping/pong 保底流量，覆盖半开连接等游戏自己也没察觉的死连接。
- 角色名行降级链：`buildRoleLine` 输出 角色名 → `角色 <id>`（区分同站多账号）→ `未知角色`，不再出现没有信息量的占位符。新文案键 `subscribeNotificationRoleId`、`subscribeNotificationRoleUnknown`。
- 测试：`tests/subscribe-notification.test.js` 覆盖 `hasBaseline` 只在全量基线后为真且 `reset` 清除、未拿到基线不判定队列为空、在线状态需确认、订阅关闭期间仍跟踪且重新开启不按旧计时推送、角色名行降级链、任务开始通知（等待队列概览口径、空队列入队只报开始、开始通知文案、开关组合的推送分工）、组队开战播报与拿不到队伍状态时的退回、行动名口径、设置弹窗消息类型顺序与默认最小间隔。长期规则见 `docs/业务功能要求.md`，需求口径同步 `docs/analysis/订阅通知需求说明书.md`。

### 地下城收益牛铃不计算收益

- 用户侧变化：地下城收益操作区在“披风不计算收益”之后新增“牛铃不计算收益”复选框（`excludeCowbellValue`），默认不勾选；勾选后牛铃和牛铃袋都不计入收益，收益结果（单个宝箱收益、每日产出、每日期望收益、每车期望收益、自定义列）与掉落物表的宝箱行展开估值同步按 0 计这部分价值。批量模拟第一行选项行同一位置共享该复选框，两侧状态同步。
- 口径：勾选后牛铃（`/items/cowbell`）与牛铃袋（`/items/bag_of_10_cowbells`）在计算路径中的 `ask/bid` 单价直接按 `0` 计——牛铃不可交易，价格由牛铃袋市场价 ÷ 10 折算，牛铃袋本身就是 10 个牛铃，两者同属牛铃收益，只排除牛铃会让口径分裂；被排除的物品不记为缺价，不影响门票与开箱钥匙等成本侧，也不影响其他物品。
- 内部变化：`calculator.js` 的 `calculate` 新增 `excludeCowbellValue` 入参并随 `outputOptions` 传入全部估值入口（收益、税前产出、掉落表宝箱行展开）；新增 `isCowbellItem` 判定，`valueExpectedDrops` 的排除判断统一收敛为 `isExcludedValue`（披风 + 牛铃），排除项单价置 0 且不进 `missingPrices`。`index.js` 在单图 uhtml 模板与批量字符串模板各加一个复选框，并把 `excludeCowbellValue` 加入 `OPTION_CONTROLS`、`SINGLE_CONFIG_FIELDS`、`calculationInput`、`computeRowResult` 与 `resetState` 默认值。文案与帮助说明在 `src/common/messages.js` 同步（`excludeCowbellValue`、`dungeonCalculatorHelp` 中英文）。
- 文档同步：`docs/analysis/地下城收益计算链路分析.md`（用户输入、排除规则、掉落表口径）与 `docs/业务功能要求.md`（两个排除开关的业务规则、批量共享选项列表；牛铃袋价格兜底顺序订正为 挂单价 → 买价折算 → 最近成交 → 牛铃袋固定参考价，与代码一致，代码不使用 `marketItemValues`）。
- 测试：新增“可选择让牛铃与牛铃袋产物按 0 计算收益”（牛铃袋 1000/800 时牛铃 ask 82、bid 65.6，排除后双双为 0 且不报缺价）与“勾选牛铃不计算收益后宝箱产出的牛铃按 0 估值，其余口径不变”（官方海盗 T0 全量市场数据下，收益差额精确等于被排除的牛铃收益、数量与成本不变、掉落表合计差额等于牛铃数量 × 税前折算价）；另有操作区选项顺序、复选框数量、批量共享选项列表、状态默认值等结构断言更新。
