### 市场交易记录「今天」、挂牌页速览层级与技能列表顺序

用户反馈三条 + 排序口径复核一条。

#### 实现

- **市场交易记录：创建时间下拉新增「今天」**（用户原话：「市场记录的创建时间下拉缺少一个今天」）：`TIME_PRESETS` 在「创建时间」之后加 `today`，标签键 `marketHistoryTimeToday`（今天 / Today），记录与统计两个页签共用；`applyTimePreset` 的 `today` 分支按本地自然日算——起止取今天 0 点与次日 0 点（上界用 `setDate` 推、不加减 24 小时，夏令时切换日也跟自然日边界），与近 N 天的滚动窗口口径并列。下拉至此为 创建时间 / 今天 / 近 7 / 15 / 30 / 60 / 90 / 180 天 / 自定义；模块头部「不给今天」的注释同步改写。
- **修复：挂牌页速览盖住市场记录弹窗**（用户原话：「左右挂牌上展示的近期价格 z-index 层高较高，文字会出现在市场记录弹窗之上……最近交易价格层高改为正常文档流的层高」）：速览 `.mst-market-history-listing-hint` 的 `z-index: 1100` 高于弹窗容器（`.mst-swal2-theme` 上的 `--mst-z-popup: 1000`）。按用户要求改用样式判定：`body:has(.mst-swal2-popup) .mst-market-history-listing-hint { z-index: auto; }`——`mst-swal2-popup` 是 MST 全部 SweetAlert2 弹窗（市场记录、提示框与各计算器）共用的统一 popup 类（`ui.js` 的 `SWAL_CLASS_NAMES`），弹窗节点只在打开期间存在于 DOM（SweetAlert2 关闭时把 `.swal2-container` 连同弹窗一起移除，已实测），因此不需要在 `didOpen` / `willClose` 里维护状态类（第一版实现如此，已按用户意见删除）。判定用统一弹窗类而不是模块自己的 `mst-market-history-dialog`，覆盖全部 MST 弹窗；Toast 的 popup 类是 `mst-swal2-toast`，不在这条规则内。
- **修复：自己的角色名片点技能报错**（用户原话：「在用户自己的名片页面应该可以点击技能，选择已学习的技能来替换，现在报错」；控制台 `Uncaught TypeError: this.getAttribute is not a function`）：`CharacterCardStandaloneRefresh.refreshCharacterCard` 绑定技能格点击时写成 `function () { this.getAttribute(...); this.skillSelector... }.bind(this)`，`this` 被绑成控制器实例、第一行就抛错，所以技能选择浮层一直打不开（该写法自 v2.7.20 引入起就没生效过）。改为箭头函数让 `this` 保持为控制器，槽位号在点击时从元素的 `data-skill-index` 读取；同时补一次性绑定（`dataset.skillSelectorBound`），避免 uhtml 增量更新复用技能格节点时每次重渲染都再叠一层监听、修好后一次点击弹出多个浮层（节点被整段替换时会重新绑定）。
- **技能列表统一按游戏的物品顺序**（用户原话：「都改为按照sortIndex排序」，指核对出的两处偏差）：`CharacterDataService.getAbilityBooks()`（`src/common/data.js`）的排序键由技能自身的 `abilityDetailMap.sortIndex` 改为技能书物品的 `itemDetailMap.sortIndex`（技能书取不到序号时才回退技能序号），技能升级计算器「添加技能」列表直接消费这个顺序；`CharacterCardSkillSelector.showSkillSelector`（`src/modules/character-card/index.js`）由角色数据的 `slotNumber` 槽位序改为同一个物品顺序，新增 `getAbilityItemIndex(abilityHrid)` 经 `DataHub.clientData.indexes.abilityBookByAbilityHrid` 取技能书序号（取不到排末尾），浮层首项「空」不变。两处偏差同源：技能自身序号把 `frenzy` 记为 44、`elemental_affinity` 记为 45，而物品序号是 `elemental_affinity`(204) 在前、`frenzy`(205) 在后；名片旧实现按槽位序把未装配技能（`slotNumber` 0）排在角色数据返回顺序的最前，与物品顺序无关。

### 强化物品价格计算器（本次新增）

需求与设计稿见 `docs/analysis/强化物品价格计算器需求说明书.md`（用户已复核全部待拍板点，结论见该文档 §七）。

#### 实现

- 新增模块 `src/modules/enhancement-cost/`：`index.js`（弹窗、目标 / 已有装备选择器、全部方案表、最优路线与逐级表、汇总）、`calculator.js`（价格口径、逐级获取成本递推、四种方案与逐级对比）、`styles.css`（模块私有样式，经 `StyleService` 注入）。
- 选择与计算口径（2026-10-16 两轮复核后的最终形态）：目标装备必选、放第一位；已有装备可选（可设为「无」），只能是目标物品本身或它的普通版，等级 ≤ 目标等级。计算只算必成路线（贤者之镜合成 / 精炼 / 解精炼 / 市场买卖），等级从低到高递推每个等级的**最低获取成本**——市场买、镜子合成（低一级主件 + 低两级普通版垫子 + 镜子）、买普通版精炼、买精炼版解精炼（拿回一半碎片）四者取最低，主件与垫子同样递归取最便宜；再列出全部四种方案（直接买成品 / 自己做 / 用已有装备当主件 / 用已有装备当垫子，含先升级再当垫子），不用已有装备的两条按「卖掉它」抵扣到手价，取净花费最低的一条作为最佳。
- 与旧实现的差别：删除了路线中途「卖出再买入」的换手动作。旧模型在「自动 = 买入取低价侧、卖出取高价侧」口径下会把买卖价差当成可重复收益——真实快照 `acrobatic_hood` +6 → +13 会走出一串「买 +8 → 卖 +8 → 买 +10 → 卖 +10 → 买 +12 → 卖 +12 → 合成」的纯换手步（甚至出现负花费）。新模型路线里不卖任何中间件，与 fastsim 的 `GearPrices.acq` / `transition` 结果对齐（`+11 → ★+13` 用已有装备当垫子 = 1.740B，与 fastsim 的 transition 完全一致）。
- 结果输出：方案汇总（总花费 / 最佳方案 / 直接买入目标成品 / 比直接买省 / 市场数据时间）、全部方案表（方案 / 花费 / 镜子 / 精炼 / 说明，最佳标绿并写「最佳」）、最优路线步骤（起点 / 卖掉已有装备 / 买入 / 合成 / 精炼 / 解精炼，含每步花费与累计）、逐级表（市场买价 / 最低获取成本 / 获取方式 / 最优路线）与税率、缺价说明。
- 入口：工具箱菜单「强化物品价格计算器」（key `enhancementCostCalculator`，图标 `item_category_currency`，排在装备提升计算器之后）；帮助浮层复用 `CalculatorHelpPopover`，`mst-enhancement-cost-help-*` 已并入 `src/common/styles/integrated.css` 的共享样式组。

### 战斗升级计算器：队友经验与悬浮「战斗」经验百分比

用户实测反馈 v2.21.0 战斗升级计算器的两个问题。

#### 实现

- **修复：队友的起始经验一律 0%**（用户实测「全都是等级 0%」）。官方名片数据（`profile_shared.profile.characterSkills`）本来带各技能 `experience`（绝对经验，与自己的角色数据同一口径；游戏客户端名片的技能页签就是用它画经验条），但 `data.js` 的 `compactProfile` 存储裁剪只保留了 `skillHrid` / `level`，而且计算器的队友分支按 `getLevelExperience(level)`（该等级 0%）返回经验——于是从队友单位打开计算器时每个专业都从 0% 起算。修正：`compactProfile` 保留 `experience`；`buildPlayerContext` 把队友快照建成 `skills: Map<skillHrid, {level, experience|null}>`（原 `levels` 字段被替换）；`getCharacterSkill` 优先用缓存经验，缺失时（v2.21.0 及更早写入的缓存，TTL 30 天）退回该等级 0% 起算；提示行在缓存没有经验时追加 `combatUpgradeLevelsNoExperience`（「名片缓存没有经验数据，起始经验按各等级 0% 计算」），并把原两条缓存提示改为「技能等级与经验来自…」。自己的实时数据路径与无参 `open()` 行为不变。
- **悬浮「战斗」技能块标题加当前经验百分比**（用户要求「专业 等级 经验百分比（最多两位小数）」）：标题行由 `<技能名> Lv.<等级>` 改为 `<技能名> Lv.<等级> <百分比>%`（例 `攻击 Lv.133 47.7%`），最多两位小数、不补零，与计算器「当前等级」列同口径；实现为纯函数 `tooltip.getSkillBlockTitle(feature, block)`；满级技能照旧整体不列（没有下一个等级）。
- **技能经验只缓存战斗技能**（用户要求「只存需要的，用不到的就不要存」）：`compactProfile` 对 `characterSkills` 按客户端 `skillDetailMap[skillHrid].isCombat` 判定——战斗技能保留 `experience`，生活技能与总等级只留 `{skillHrid, level}`（全项目只有战斗升级计算器读这份经验，名片渲染 / 评分 / 战斗模拟导出都只用等级）；判定不了（客户端字典尚未就绪、首次打开）时整份保留，等下一次写入再裁。`DataHub.init()` 相应把 `initClientDataFromCache()` 调到 `loadStoredProfiles()` 之前，让加载期的重写一次裁到位（字典本来就只依赖 localStorage，不读名片）。

### CSS 类名统一（跨模块共用组件）
