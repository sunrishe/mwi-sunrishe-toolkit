## 当前状态：v2.17.2 装备提升模拟口径、自动模拟与响应速度（2026-09-24）

### 装备提升模拟标靶口径

- 用户侧变化：标准标靶按设定的 1 万亿生命值、62 点护甲与抗性、320 闪避参与模拟，3 小时模拟中不会死亡；每秒伤害数值整体提高约三成，九职业基准值随之重算。
- 配置口径：标靶属性只能写在基础字段上（`staminaLevel`、`defenseLevel`、`combatStats.maxHitpoints`、`combatStats.armor` 等），模拟器会按游戏公式重算派生属性；`CombatSimulationService` 用 `TARGET_STAMINA_LEVEL`、`TARGET_INTELLIGENCE_LEVEL`、`TARGET_DEFENSE_LEVEL`、`TARGET_ARMOR` 提供这些值，派生字段仍写成最终值便于与基准文档对照。规则见 `docs/analysis/装备提升模拟基准说明.md`。
- 测试：新增“基础字段按游戏公式得到统一属性”断言（生命值、魔力值、护甲、抗性、闪避），九职业固定种子回归断言真实模拟中标靶死亡记录为 0，基准值按同款加载逻辑与固定种子重新生成。

### 装备提升同装备直接给出结果

- 用户侧变化：基准装备与对比装备是同一件（同 HRID、同强化等级）时直接给出 0 提升，不启动模拟，两栏每秒伤害显示“—”。选择基准装备后对比装备默认跟随，打开弹窗的默认状态即属于该情况。
- 实现：`EquipmentComparisonService.isIdenticalSelection` 命中时 `compare` 直接返回 `{baselineDps: null, comparisonDps: null, change: 0}`，不创建 Worker；价格差为 0 时“每 1000 万提升”保持不可用。
- 测试：新增用例覆盖同强化等级直接短路、不同强化等级仍走模拟，以及对比装备跟随基准装备时不触发模拟并得到 0 提升。

### 装备提升打开后自动模拟

- 用户侧变化：打开弹窗、切换职业方案后立即开始模拟，空闲态显示“等待计算”。
- 实现：`didOpen` 在 `render()` 且 root 就绪后调用 `requestSimulation()`（结果回调会校验 root，过早请求会被丢弃），`handlePresetChange` 末尾同样请求；空闲态文案改为 `dpsPending`，不再使用 `dpsDataUnavailable`。
- 测试：新增“切换职业方案后自动请求模拟”“打开弹窗后立即请求模拟”两条用例；`tests/core-regression.test.js` 的术语断言同步更新。

### 装备提升模拟口径与渲染性能

- 用户侧变化：模拟不计入角色成就与公会神龛等固定增益，结果只反映所选装备本身；搜索和切换装备的响应明显更快。
- 口径：模拟数据不传入成就，成就 tier 表与完成度表一并置空（只清空完成度表会把每个 tier 判为已达成）。
- 性能：角色物品按 HRID 建索引并按内容签名复用，候选装备列表按装备表、方案与角色物品缓存；渲染路径改用轻量的 `buildSelectionContext`，不再构造完整模拟上下文。通用规则见 `docs/工程结构与开发规范.md`。
- 实测（真实角色数据与物品表 957 项）：一次视图计算由 11.11 ms 降到 0.32 ms（缓存命中），角色物品变化后的首次重建 4.06 ms。
- 测试：新增“候选装备列表按角色物品缓存，角色物品变化后重新生成”“模拟数据不计入角色成就”断言。
