## 一、需求（用户原始描述 + 已确认的取舍）

把第三方脚本《[银河奶牛]显示战斗升级所需时间 v1.4》（`references/legacy-scripts/战斗升级时间/[银河奶牛]显示战斗升级所需时间_v1.4.js`，已阅读全部 250 行）的能力整合进工具箱，并按下面 5 条改造：

1. **不只在每个战斗技能后显示**，而是在导航栏「战斗」项、以及各战斗技能上悬浮显示。（2026-10-13 用游戏数据复核：`focusTraining` 只存在于 7 个战斗技能护符上，生活技能护符的 `combatStats` 为空、只有 `noncombatStats`，所以「护符职业 / 主修职业」一定落在 7 个战斗技能内，与决策表「只列出战斗技能」一致。）
2. **悬浮「战斗」导航项**时，先增加横杠，展示格式：

   ```text
   战斗
   --------------
   与怪物战斗。你的战斗等级代表了基于各个战斗技能等级组合的综合战斗效果。
   --------------
   攻击 Lv.当前等级 当前经验百分比%
   升级所需时间：
   升级具体时间：
   Lv等级升级所需时间：
   Lv等级升级具体时间：
   --------------
   魔法 Lv.当前等级 当前经验百分比%
   （同上 4 行）
   ```

3. **悬浮战斗技能**时，在「升级所需经验」后拼接同样 4 行。
4. **交战界面**（战斗 → 交战）每个玩家单位 `CombatUnit_combatUnit__1m3XT` 上加一个入口，点击打开战斗升级计算器，自动填入该玩家的主修/选修经验，列表按该玩家的等级与经验填充。
5. 计算器里在合适位置显示**玩家名称**，避免不知道是谁的数据。

## 二、已核对的游戏事实（实现时直接依赖，不要再猜）

### 2.1 导航栏悬浮提示结构

`main.8add56c3.chunk.js` 里 `NavigationBar.renderTooltipContent`：

```jsx
<div className={navigationSkillTooltip}>        // NavigationBar_navigationSkillTooltip__3a9Rz
  <div className={name}>{名称}</div>            // NavigationBar_name__jAIEQ
  {/* 仅当该导航项有 skillHrid 时才有的 3 个 div： */}
  <div key="level">等级: N</div>
  <div key="totalExperience">总经验: N</div>
  <div key="xpToLevelUp">升级所需经验: N</div>  // ← 4 行内容插在它后面
  <div className={info}>{tooltipInfo 文案}</div> // NavigationBar_info__3zahT
</div>
```

- **「战斗」导航项**的提示框只有 **2 个子元素**：`name`（= 中文「战斗」/ 英文 `Combat`）+ `info`（战斗说明）。
- **战斗子技能**的提示框有 **5 个子元素**（多出「等级/总经验/升级所需经验」3 行）。
- 判断依据就是子元素个数与是否存在「升级所需经验」行，不要靠中文文案匹配（游戏新增了 7 种语言）。

导航项数据结构（`Co` 常量）与图标来源：

- 「战斗」项：`{name: 'navigationBar.combat', iconSrc: Be.MiscIcons.Combat, value: NavConsts.Combat, tooltipInfo: 'navigationBar.combatTooltip', subSkills: [7 个战斗技能]}`。
- 子技能项：`{iconSrc: Be.getSkillIconSrc(技能), skillHrid: '/skills/xxx', tooltipInfo: 'navigationBar.xxxTooltip'}`。
- 子技能行 DOM：`MUI Tooltip > div.NavigationBar_nav__3uuUl > [svg 图标, div.NavigationBar_contentContainer__1x6WS]`。
- 图标写法：`<svg><use href="<sprites>.svg#<片段>">`。技能图标在 **skills sprite**（`skills_sprite.3bb4d936.svg`，片段 `stamina|intelligence|attack|defense|melee|ranged|magic`），「战斗」导航项在 **misc sprite**（`misc_sprite.02869244.svg`，已确认存在 `id="combat"`）。
- 因此**从悬浮目标行的图标反推目标**是最稳的做法（不依赖语言）：
  - 图标 sprite 含 `skills_sprite` → 战斗技能，`skillHrid = '/skills/' + 片段`；
  - 图标片段为 `combat` 且 sprite 为 misc → 「战斗」导航项。
- `info` 行**自带分隔线**：游戏 CSS 里 `.NavigationBar_info` 是 `margin-top: var(--spacing-xs)` + `border-top: 1px solid #000` + `padding-top: var(--spacing-xs)`，所以「战斗」提示框里「战斗」与说明文字之间那条横杠是游戏原生的，不需要我们画。
- 满级（200 级）时游戏**仍会渲染**「等级 / 总经验 / 升级所需经验」3 行（`renderTooltipContent` 对带 `skillHrid` 的项无条件 push，满级时「升级所需经验」为 0），所以「子元素个数」这条兜底判据在满级也成立。

### 2.4 护符（Charm）与「主修/选修」的游戏口径

官方补丁说明（`main.8add56c3.chunk.js` 的 patchNotes）原文要点：

- 护符是每个技能都有的装备（`/items/{trainee,basic,advanced,expert,master,grandmaster}_<技能>_charm`，共 102 件），装备在护符槽。

## 三、算法

### 3.1 逐技能小时经验（速率）

```text
elapsedSeconds = (now - new Date(gameState.combatStartTime).getTime()) / 1000
若 elapsedSeconds < 60 → 本场数据不可用（返回 null，不显示任何时间）
rate(skillHrid) = totalSkillExperienceMap[skillHrid] / elapsedSeconds * 3600   // 只保留 > 0 的
```

> ⚠️ 现有实现 `combat-upgrade/index.js` 的 `getBattleExperienceFill` 用的是 `Math.max(1/3600, …)` 小时下限（即 1 秒兜底）。按用户第 3 条决策，**新老路径统一改成 60 秒下限**：`getBattleExperienceFill` 与新的悬浮/入口都走同一份速率计算，避免同一份数据两个口径（几秒取样会把速率放大几十倍）。

### 3.2 剩余时间与具体时间

```text
needExp(level, experience)     = getLevelExperience(level + 1) - experience          // 升下一级（getLevelExperience 会把参数夹到 0–200，满级见下）
needExpMilestone(level, exp)   = getLevelExperience(milestone) - exp                 // 到下一大等级
milestone(level)               = 低于 119 级：下一个 10 的整数倍（110 → 120、118 → 120）
                                 119 级起：下一个 5 的整数倍（119 → 120、133 → 135、150 → 155）
                                 若 milestone > 200 → 这两行不显示（197 级起）
remainingSeconds               = needExp / rate * 3600（向上取整）
specificTime                   = now + remainingSeconds（本地时区）
```

- 时长格式（新增 i18n 单位键，`dayUnit` 已存在）：
  - zh：`1 年 2 天 3 小时 20 分`；en：`1 y 2 d 3 h 20 m`；分量只为 0 时显示 `0 分`。
- 具体时间格式（**沿用原脚本**）：

  ```js
  const days = Math.floor(seconds / 86400);
  // 超过 30 天且跨年度才补年份，平时只到分钟
  return days >= 30 && upgradeYear > currentYear ? `${y}/${mm}/${dd} ${HH}:${MM}` : `${mm}/${dd} ${HH}:${MM}`;
  ```

- **速率行 + 四行文案**（标签 + 全角冒号 + 值，逐行一个 `<div>`；沿用用户给的格式与原脚本的单行写法）：第一行是 `经验速率：<速率>K/h`（用户要求展示速率；与计算器输入框同口径：一位小数、去掉多余的 0），随后 `升级所需时间：<时长>`、`升级具体时间：<MM/DD HH:mm>`、`Lv.{里程碑} 升级所需时间：<时长>`、`Lv.{里程碑} 升级具体时间：<MM/DD HH:mm>`；技能块标题行为 `<技能名> Lv.<当前等级> <经验百分比>%`（例：`攻击 Lv.133 12.34%`；百分比最多两位小数、去掉多余的 0，与计算器「当前等级」列同口径，2026-10-14 用户要求加入）。
- **满级（200 级）没有下一个等级**：经验表只到 200 级（`levelExperienceTable` 下标 0–200，200 级已没有「升级所需经验」，直接算会得到 0）。满级时这 4 行都不显示——技能悬浮框不注入，「战斗」块里也不列该技能（与「没有数据的技能不显示」同一口径）。

### 3.3 主修/选修经验填充

沿用现有 `getExperienceFillFromRates` 的 3:7 拆分与「读到 2 个职业按当前列表类型分别填」规则，**不改口径**，只是把输入换成指定玩家的速率。

### 4.2 `planner.js`

```js
// 战斗升级里程碑常量（MAX_SKILL_LEVEL 与 COMBAT_SKILL_HRIDS 由 planner.js 导出，
// 计算、悬浮与弹窗列表共用一份，避免多处硬编码）
const MILESTONE_LOW_LEVEL_LIMIT = 119;   // 低于 119 级按 10 的整数倍
const MILESTONE_LOW_LEVEL_STEP = 10;
const MILESTONE_HIGH_LEVEL_STEP = 5;     // 119 级起按 5 的整数倍

// 下一大等级；超过 200 级返回 null（调用方据此隐藏「Lv 等级」两行）
getMilestoneLevel(level) {
  const safeLevel = Math.max(0, Math.floor(Number(level) || 0));
  const step = safeLevel < MILESTONE_LOW_LEVEL_LIMIT ? MILESTONE_LOW_LEVEL_STEP : MILESTONE_HIGH_LEVEL_STEP;
  const nextLevel = (Math.floor(safeLevel / step) + 1) * step;
  return nextLevel <= MAX_SKILL_LEVEL ? nextLevel : null;
}

// 技能状态解析器：外部玩家（队友）用快照，自己用实时角色数据。
resolveSkillState(getSkillState, skillHrid) {
  if (typeof getSkillState === 'function') return getSkillState(skillHrid) || {level: 0, experience: 0};
  const {CharacterDataService} = this.ctx;
  return CharacterDataService.getCharacterSkill(skillHrid) || {level: 0, experience: 0};
}
```

- `getDefaultPrimarySkillHrid(getSkillState)`、`calculatePlan(rows, primaryRate, secondaryRate, getSkillState)`、`getPlanRowContext(row, sequenceById, previousBySkill, CharacterDataService, utils, getSkillState)` 内部把 `CharacterDataService.getCharacterSkill` 换成 `this.resolveSkillState(getSkillState, hrid)`；`actual.level` / `actual.experience` 的兜底保持不变。
- **默认参数为 `undefined` → 行为与现在完全一致**，现有 602 行测试不应改动。

### 4.3 `index.js`

### 4.4 `tooltip.js`

1. **登记当前悬浮的导航行**（不依赖 MUI 内部结构，最稳）：
   - `document.addEventListener('mouseover'/'mouseout', handler, {capture:true, signal})`（用 AbortController 便于清理）。
   - 在 mouseover 时用 `closest()` 找到导航行（`.NavigationBar_nav__`, `.NavigationBar_navigationLink__`），调 `readNavTarget(element)` 得到 `{kind:'skill'|'combat', skillHrid}` 并记入 `this.hoveredTarget`；离开导航行时清空；**行元素与上一轮相同就忽略**（行内移动会重复触发 mouseover）。
   - `readNavTarget` 取图标时必须跳过 `NavigationBar_toggleContainer`（行内第一个 `svg use` 是「战斗」项的折叠三角，跳不过去就永远识别不出「战斗」项——真机实测）。
2. **每帧注入**（`mount(feature)`，被公共观察器按帧调用）：
   - `document.querySelectorAll('[class*="NavigationBar_navigationSkillTooltip"]')`（通常 0～1 个）。
   - **目标识别以提示框自身为准**：子元素 ≤ 2 → 「战斗」项；否则取第一个子元素（名称）与 7 个战斗技能的本地化名（`DataHub.getLocalizedGameName('skillNames', hrid)`）比对；比对失败（游戏新增语言等）时才退回 `hoveredTarget`，**且必须确认该提示框属于当前悬浮行**（行文本以提示框名称开头）——同一时刻可能残留正在关闭的提示框，不比对这个会把别行的数据写进来（真机实测）；生活技能的目标不进注入分支。
   - **技能项**（`kind:'skill'`，且速率可用）：
     - 注入容器 `<div class="mst-combat-tooltip-time">`，插在「升级所需经验」那一行之后、`NavigationBar_info` 之前（与原脚本一致）。
     - 内容为速率行 + 4 行，文案与格式见 §3.2（`经验速率：{速率}K/h` / `升级所需时间：…` / `升级具体时间：…` / `Lv.{里程碑}` 两行）；满级技能不注入（§3.2）。
   - **「战斗」项**（`kind:'combat'`，且有任意技能速率）：
     - 在 `NavigationBar_info` 之后追加块：
       ```
       <div class="mst-combat-tooltip-divider"></div>
       每个有数据的战斗技能（按客户端 skillDetailMap.sortIndex 排序）：
         <div class="mst-combat-tooltip-skill">攻击 Lv.133</div>
         + 上面 4 行
         <div class="mst-combat-tooltip-divider"></div>   // 技能块之间
       ```
     - 分隔线共 3 处（对应用户格式里的三条横杠）：①「战斗」标题与说明之间那条是**游戏原生**的（`.NavigationBar_info` 自带 `border-top`，§2.1）；②「说明」与技能块之间，由注入块的 `border-top`（或块首 divider）实现；③ 技能块之间用 divider。注入块整体追加在 `NavigationBar_info` 之后。
     - 「战斗」块里的等级与时间都取**玩家自己**：等级来自 `CharacterDataService.getCharacterSkill`，速率来自自己在 `battlePlayers` 里那份（悬浮的本来就是自己的导航栏）。
   - **按轮次冻结（用户要求）**：进入新的导航行时递增 `hoverToken`，内容在同一轮悬浮期间只计算一次（提示框元素上记 token，一致就整帧跳过），数字不会一边悬浮一边跳；移开再悬浮才重新读取最新数据。行内移动（图标与文字之间）会重复触发 mouseover，必须比较行元素后才算新一轮。
3. **样式**：提示框是浅色背景（游戏 MUI tooltip 背景 `rgba(187,197,241,.95)`，`pointer-events: none`）。分隔线必须与游戏原生一致：`border-top: 1px solid #000` + `margin-top`/`padding-top` 各 0.25rem（= 游戏 `--spacing-xs`，就是 `.NavigationBar_info` 自带那条线的样式；用户反馈过颜色不能偏浅），用 div 而不是 `<hr>`（不受游戏 reset 影响）；文字颜色继承，字号与游戏一致。提示框还带 `disableInteractive`（鼠标移不进提示框内部），**注入内容只能是纯文本，不要放按钮等交互元素**。
4. **降级**：拿不到速率（不在战斗 / 不足 60 秒 / 该技能本场无经验）→ 什么都不注入，保持游戏原有的提示框外观。

### 4.5 `battle-entry.js`

1. `mount(feature)`：`document.querySelectorAll('[class*="CombatUnit_combatUnit"]')`，对每个单位：
   - 已经含 `.mst-combat-unit-entry` 就跳过。
   - 从 React fiber 取 `combatUnit`：单位 div 自己的 props 只有 className/onClick/children（已核对），`utils.getReactProps(el)` 拿不到 `combatUnit`；用 `DataHub.getReactFiber(el)`（`src/common/data.js` 已提供）**沿 fiber 向上找 `memoizedProps.combatUnit`**：

     ```js
     const fiber = DataHub.getReactFiber(el);
     let node = fiber;
     let unit = null;
     while (node && !unit) {
       unit = node.memoizedProps?.combatUnit || null;
       node = node.return;
     }
     ```

   - `unit.isPlayer !== true` → 跳过（怪物没有主修/选修）。
   - 追加按钮：

     ```html
     <button
       type="button"
       class="mst-combat-unit-entry"
       title="战斗升级计算器（dadada6）"
       data-character-name="dadada6"

       <svg aria-hidden="true"><use href="<misc_sprite>#experience"></use></svg>
     ```

   - 点击：`event.preventDefault(); event.stopPropagation();` → `feature.open({characterId, name})`。
2. **悬浮才显示**（不往游戏元素上加 class，React 会覆盖）：

   ```css
   .mst-combat-unit-entry {
   ```

4. **性能**：只有交战页才有这些元素；每帧最多十几次 `querySelectorAll`，与现有模块量级一致。注入前判断是否存在，避免重复插入。
5. **刷新与清理**：单位被 React 重建时按钮会消失，下一帧自动补回；`refreshLanguage` 只需更新 `title`。

## 九、风险与待确认

### 九.0 待用户点头（2026-10-13 复核新增）

1. **入口按钮的显示方式**：决策表记的是「鼠标悬浮时才出现的按钮」，而原始要求写的是「醒目容易察觉的入口」——两者有张力（悬浮前完全不可见）。如果希望一眼就能看到，可改成常显低透明度 + 悬浮高亮，其余交互不变。
2. **「大等级」口径（2026-10-13 用户更正，已实现）**：低于 119 级取**下一个 10 的整数倍**等级（110 → 120、118 → 120），119 级起取**下一个 5 的整数倍**等级（119 → 120、133 → 135）。
3. **满级（200 级）行为**按 §3.2 处理（4 行都不显示）；若要显示「已满级」等文案请说明。

### 九.1 原风险清单（沿用）

1. **悬浮目标识别（已实现并实测）**：最终口径是「以提示框自身为准（子元素个数 + 名称反查）+ 悬浮行兜底」，悬浮行只用于名称反查失败时、且必须与提示框名称匹配；两次真机实测分别发现并修掉了折叠三角取图标与关闭中提示框被误注入的问题，`aria-describedby`/popper id 没有用到。
2. **游戏类名会随版本更新变化**：`NavigationBar_nav__*`、`NavigationBar_navigationSkillTooltip__*`、`CombatUnit_combatUnit__*` 都是带 hash 的 CSS Module 类名，代码里必须用 `[class*="前缀"]` 形式（现有 `GameUiAdapter` 就是这么做的）。
3. **`战斗` 悬浮块较长**：7 个技能全有数据时约 30 行，可能超出视口。游戏 tooltip 自身有 `max-height: 100vh; overflow-y: auto`，短屏需要实测；若观感差，再按用户确认后的方案截断（例如只显示前 N 个或折叠）。
4. **队友经验百分比（2026-10-14 更正并修复）**：原文假设「名片缓存没有 experience」，实测与游戏源码都表明官方名片自带各技能 `experience`（客户端名片技能页签就是用它画经验条），问题出在 MST 存缓存时把它裁掉了、计算器也只读等级——结果队友全部显示 0%。现已保留并使用该字段（见 §十），只有旧缓存没有经验时才按该等级 0% 起算并在提示行写明。
5. **`getBattleExperienceFill` 的 60 秒下限**改变了现有「使用当前战斗经验」按钮的边界行为（原先 1 秒即可），需在更新日志中作为用户可感知变化写明。

## 十、2026-10-14 修正（并入 v2.22.0）

用户实测反馈两个问题，均已修复并补测试：

1. **队友经验一律 0%（修复）**
   - 现象：从队伍成员的战斗单位打开计算器时，各专业都从 0% 起算，看什么都是「等级 0%」。
   - 原因：官方名片数据（`profile_shared.profile.characterSkills`）本来带 `experience`（绝对经验，与自己角色数据同一口径，客户端名片技能页签用它画经验条），但 `data.js` 的 `compactProfile` 存储裁剪只保留了 `skillHrid` / `level`，且 `getCharacterSkill` 的队友分支按 `getLevelExperience(level)`（该等级 0%）返回经验。
   - 修正：`compactProfile` 保留 `experience`；`buildPlayerContext` 把队友快照建成 `skills: Map<skillHrid, {level, experience|null}>`；`getCharacterSkill` 优先用缓存经验，缺失（v2.21.0 及更早写入的缓存）时退回该等级 0% 并追加 `combatUpgradeLevelsNoExperience` 提示。
   - 影响面：只影响队友上下文；自己的实时数据路径与旧的无参 `open()` 行为不变。
2. **悬浮「战斗」技能块标题加经验百分比（用户要求）**
   - 标题从 `<技能名> Lv.<等级>` 改为 `<技能名> Lv.<等级> <经验百分比>%`（例：`攻击 Lv.133 12.34%`）；格式与计算器「当前等级」列一致——`toLocaleString(locale, {maximumFractionDigits: 2, minimumFractionDigits: 0})`，最多两位小数、不补零。
   - 实现为 `tooltip.getSkillBlockTitle(feature, block)`（纯函数，便于断言）；满级技能照旧整体跳过（没有下一个等级，百分比无意义）。
3. **技能经验只缓存战斗技能（用户要求：只存需要的）**
   - 规则：`compactProfile` 对 `characterSkills` 按客户端 `skillDetailMap[skillHrid].isCombat` 判定——战斗技能保留 `experience`，生活技能与总等级只留 `{skillHrid, level}`；判定不了（客户端字典尚未就绪）时整份保留，等下一次写入再裁。
   - `DataHub.init()` 因此把 `initClientDataFromCache()` 调到 `loadStoredProfiles()` 之前，让加载期的重写一次裁到位。
   - 依据：全项目只有战斗升级计算器读这份经验（名片渲染、评分、战斗模拟导出都只用等级），生活技能经验是纯占位。测试：`tests/core-regression.test.js` 的裁剪用例（战斗保留 / 生活与总等级丢弃）、读取重写用例、`keepsSkillExperience` 的字典未就绪分支与初始化顺序断言。
