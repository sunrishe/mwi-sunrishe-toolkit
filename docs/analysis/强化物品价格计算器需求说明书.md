## 一、需求原文与解读

### 1.1 用户原话（按原样保留）

> 现在准备开发一个新功能，强化物品价格计算器。
> 基本逻辑：参考装备提升计算器，选择基准装备和目标装备以及强化等级，下面用列表计算出每一级强化的花费，以及当前最优方案。
>
> 1. 选择基准装备和强化等级，然后选择目标装备和强化等级，目标装备的强化等级必须大于基准装备，并且目标装备只能是基准装备或者基准装备的精炼物品。
> 2. 选择出售方式和购买方式，出售和购买分三个选项吧，自动（默认选项）、左一、右一，自动表示程序根据最优价格自动计算。
> 3. 根据上面的信息，按照强化等级逐等级计算每一级最划算的方案。
>
> 基础知识：
>
> 1. 部分装备是允许精炼的，可以到 init_client_data 去看。
> 2. 强化物品升级是 n=(n-1)+(n-2)+贤者之镜，也可以直接在市场购买，市场没有则只能通过贤者之镜合成。
> 3. 某些物品如果要在市场卖出，需要计算 4% 的市场税，这是有全局变量的，因为以后可能发生更改，实际所得为 96%。
>
> 补充：精炼物品是允许通过精炼物品+普通物品+贤者之镜来合成的。

### 1.2 复核答复（2026-10-14，用户的拍板结论）

| #   | 议题             | 用户结论                                                                                                                   |
| --- | ---------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1   | 「自动」价格口径 | **取成本最低的**：买入取更低的一侧价、卖出取更高的一侧价                                                                   |
| 2   | 基准装备         | **允许是精炼物品**                                                                                                         |
| 3   | 精炼与换手时机   | **每一步都允许精炼，每一步也允许卖出精炼再购入普通物品或者精炼物品，主要看该步骤操作的最优价格**（即不再固定「最后精炼」） |
| 4   | 保护物品         | **保护物品就是贤者之镜，没有其他的，而且成功率 100%**                                                                      |
| 5   | 普通强化         | **不纳入，只算必成路线**（计算器只采用 100% 成功的操作：贤者之镜合成、精炼、市场买卖换手）                                 |

### 1.3 需求解读（设计输入）

> 2026-10-16 按用户复核（§7.3）调整了选择方向：**目标装备必选、放在第一位；「基准装备」改名「已有装备」并变为可选项，且限定为目标物品本身或它的普通版**。下表与 §四按调整后的口径描述。

| 需求点       | 解读                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| 目标装备     | 必选，带一个强化等级 `t`（0–20）；它决定整个计算以哪条线（普通 / 精炼）为准                                    |
| 已有装备     | 可选（可设为「无」）：只能是目标物品本身或它的普通版，带一个强化等级 `b`，`b ≤ t`                              |
| 买卖方式     | 计算中所有买入按「购买方式」计价、所有卖出按「出售方式」计价，三档：自动（默认）/ 左一 / 右一                  |
| 逐级计算     | 从 `b+1`（没有已有装备时从 +1）到 `t` 逐级列出直接买与自己做哪个更便宜                                         |
| 当前最优方案 | 按等级递推每个等级的最低获取成本（市场买 / 镜子合成 / 精炼 / 解精炼），再列出全部方案并标出最便宜的一种（§四） |
| 计算口径     | 全部操作 100% 成功，所有数字都是**确定花费**；失败概率（普通强化）不进计算                                     |

说明：「装备提升计算器」指工具箱现有模块「装备提升计算器」（`src/modules/equipment-comparison/`），其「装备选择器（含强化等级下拉）+ 搜索选择面板」的交互形态是本功能的参照。

## 二、已核对的游戏事实（实现时直接依赖）

以下全部来自 `main.8add56c3.chunk.js` 与 `init_client_data.json` 的实际核对，不是猜测。其中 2.1/2.2 的「普通强化与保护物品」按用户决定**不进入计算模型**，保留记录用于解释口径与后续参考。

### 2.1 装备与强化等级

- 可强化装备（`itemDetailMap` 中带 `enhancementCosts`）：当前数据共 **532 件**（含 38 件精炼物品）；进入选择的只有这批装备。
- 强化等级范围 **0–20**（成功率表 20 项覆盖 +0→+1 至 +19→+20；属性加成表 21 项；市场等级键最大 20）。
- 普通物品与对应精炼物品的 `enhancementCosts` 完全相同（逐条比对 acrobatic_hood / anchorbound_plate_body / regal_sword 等，材料、数量、金币一致）。
- 每次强化动作消耗一份 `enhancementCosts`（物品 + 数量，含 `/items/coin`，金币单价按 1 计）。
- 强化成功率表 `enhancementLevelSuccessRateTable`（记录备查，不参与计算）：按当前等级索引为 `50% / 45% / 45% / 40% / 40% / 40% / 35% / 35% / 35% / 35% / 30%…`。

### 2.2 普通强化的失败与保护（记录备查，不参与计算）

- 游戏内帮助文本：「if the enhancement process fails, the level is reset to 0」——无保护失败时强化等级重置为 0。
- 游戏内文案 `enhancingProtectionContent`：「One protection item is consumed on failure to ensure that only 1 enhancement level is lost instead of being reset to 0. Philosopher's Mirror is always consumed and guarantees success.」——保护物品失败时消耗 1 个、只掉 1 级；贤者之镜必定成功。
- 保护物品候选（源码 `getValidProtectionItemHrids`）＝ `protectionItemHrids`（159 件物品带此字段）+ 物品自身 + 保护之镜 + 贤者之镜。
- **按用户决定**：计算器不使用普通强化路线，也不使用「贤者之镜以外」的保护物品；界面上不出现这些选项。

### 2.3 贤者之镜（本功能唯一的「强化」手段）

- 贤者之镜 `/items/philosophers_mirror` 物品描述：
  > When used as protection, the enhancement is guaranteed to succeed and the enhancing cost changes to a copy of the base item at one enhancement level below the primary item.
- 源码 `getPhilosophersMirrorCost(item)`：消耗 = **1 个基础物品 @ `max(0, 当前等级 - 1)`**；
- 基础物品的取法 `getBaseItemHridForPhilosophersMirror`：有 `baseItemHrids` 取第一项（精炼物品 → 普通物品），否则取物品自身。
- 用镜子时**强化消耗从 `enhancementCosts` 整体替换为上面这一项**（源码：`if 镜子 → getPhilosophersMirrorCost(...) else enhancementCosts`），镜子本身「always consumed」，且**必定成功**。
- 因此用户的公式完全成立（主物品 → 结果）：
  - 普通物品：`+n = +(n-1) + +(n-2) + 贤者之镜`；
  - 精炼物品：`+n 精炼 = +(n-1) 精炼 + +(n-2) 普通 + 贤者之镜`（基础物品取 `baseItemHrids[0]`，即普通版）。
- 单步成本：`+k → +(k+1)` 的合成成本 =（1 个基础物品 @ `max(0, k-1)` 的买入价）+（1 个贤者之镜买入价），100% 成功。

### 2.4 精炼

- 当前数据共 **38 件**可精炼装备，精炼物品 hrid = 基础物品 hrid + `_refined`，物品名带「★」后缀；`baseItemHrids` 指向唯一的基础物品（一一对应）。
- 精炼动作（`actionDetailMap` 中 `upgradeItemHrid === 基础物品` 且输出精炼物品的 38 个生产动作，分属奶酪锻造 / 缝纫 / 手工）：
  - 输入 = 基础物品本身（手持） + 精炼碎片（`pirate_refinement_shard` 等，数量 100 或 300，按物品档位）；
  - 输出精炼物品 1 个；`retainAllEnhancement: true`，**保留强化等级**（+b 普通 → +b 精炼）；
  - 生产类动作必定成功；有生产技能等级要求（104–106 等），本功能只算材料费用、不校验技能是否达标。
- 精炼只在 普通线 → 精炼线 方向可用（游戏内不可逆；市场换手可以「卖精炼买普通」绕回，见 4.3）。
- 相关但不纳入：分解（unrefine）、炼金转化（transmute），见 §八。

### 2.5 市场与税率

- 市场数据（MWITools 缓存 / 官方接口同构）：`marketData[itemHrid][强化等级] = {a, b, p?, v?}`：
  - `a` = 左一（最低卖价 / ask）、`b` = 右一（最高买价 / bid）、`p` = 最近成交价、`v` = 成交量；缺价为 `-1`。
- 市场税率：工程全局常量 `MARKET_TAX_RATE = 0.04`（`src/common/constants.js`）；**卖出到手 = `floor(报价 × 96%)`**（税向上取整 / 到手向下取整）。不涉及牛铃袋等 18% 特殊税。
- 市场里同一物品不同等级可能有 / 没有挂单（例：`acrobatic_hood_refined` 样例数据只有 +10 与 +12），买卖动作必须逐等级判可用性。

## 三、需求逻辑自洽性分析

### 3.1 结论总览

| 类别             | 结论                                                                                                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 与游戏一致       | 镜子合成公式（普通 / 精炼两条）；4% 市场税与 96% 到手；精炼保留强化等级；已有装备只能是目标物品或它的普通版；等级范围 0–20                                             |
| 已按用户决定定型 | 只算必成路线（普通强化与保护概率不进模型）；逐级递推最低获取成本（市场买 / 镜子 / 精炼 / 解精炼）；全部方案列出并标最佳；目标必选、已有装备可选；自动=取成本最低的一侧 |
| 已闭环           | 原待拍板 12 项（§7.1）与两轮复核（§7.2–7.3）全部有结论，本文档按结论定型                                                                                               |

### 3.2 逐条分析

**（1）「强化物品升级是 n=(n-1)+(n-2)+贤者之镜」——与游戏一致，且按用户决定它就是本功能的唯一升级方式。**

该公式是「用贤者之镜保底」的确定性路径（源码 `getPhilosophersMirrorCost`）。游戏里另有普通强化（消耗材料、按成功率、失败归 0），但用户明确决定**不纳入**（只算必成路线），因此本功能中「升级」只有镜子合成一种动作，全部 100% 成功；「市场没有则只能通过贤者之镜合成」在本模型下完全成立。

**（2）「实际所得为 96%」——与游戏一致。** 精确口径是「到手 = `floor(报价 × 96%)`」。工程已有 `MARKET_TAX_RATE` 全局常量，直接复用，不写字面 0.96。

**（3）已有装备只能是「目标物品本身」或「它的普通版」——与游戏结构一致。** 精炼物品与基础物品一一对应（38 件），精炼时保留强化等级；已有装备选精炼版时目标也只能是同一件精炼物品，选普通版时目标可以是普通版（继续升级）或精炼版（升完再精炼）。

**（4）「每一步都允许精炼、每一步也允许卖出再购入」——落为「按等级递推的最低获取成本 + 四种方案」，不做路线中途的卖出。**

2026-10-16 用户复核后修正：把模型改成 mwi-fastsim「装备获取成本」的思路——先按等级从小到大算出每个等级最便宜的获取方式（市场买 / 镜子合成 / 买普通版精炼 / 买精炼版解精炼，主件与垫子同样按最便宜方式获取），再把「直接买成品 / 自己从零做 / 用已有装备当主件 / 用已有装备当垫子」四种方案全部列出、取净花费最低的一条并标为最佳（§4.3–4.4）。旧模型允许路线中途「卖出再买入」，在「自动 = 买低侧 / 卖高侧」口径下会把买卖价差算成可重复收益（价差超过约 4.17% 的物品都能靠买入再卖出净赚），路线里出现一串纯换手步骤甚至负花费；新模型里路线不卖出任何中间件，「卖掉已有装备」是唯一一次卖出，并且只作为「不用它」那两类方案的抵扣。

**（5）目标等级与已有等级的关系——已有等级 ≤ 目标等级。** 相等时唯一有意义的做法是「用已有装备当主件」（花费 0，本来就有）或跨版本精炼；目标为普通版、已有装备为精炼版这种反向组合不允许（§4.7）。

## 四、计算模型设计（按等级递推的最低获取成本 + 四种方案）

### 4.1 术语

| 术语       | 含义                                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| 基础物品 B | 目标物品的普通版（如 `acrobatic_hood`）                                                               |
| 精炼物品 R | B 的精炼版本（如 `acrobatic_hood_refined`）；B 无精炼版本时只有普通线                                 |
| 目标       | `(Lt, t)`，Lt ∈ {B, R}，t ∈ [0, 20]：**必选**，整条计算以它为准（第一条线就是它的那条）               |
| 已有装备   | `(L0, b)`，可选（不选时记为空）：只能是目标物品本身（L0 = Lt）或它的普通版（Lt = R 时 L0 = B），b ≤ t |
| 获取成本   | `acq(line, k)`：不借助已有装备、从市场把「line 版本的 +k」弄到手的最便宜花费                          |
| 方案       | 在「直接买成品 / 自己做 / 用已有装备当主件 / 用已有装备当垫子」四种做法里的一个候选（全部列出）       |

### 4.2 价格口径

两个下拉共用同一套取值规则，作用于计算中的**每次买入与卖出**：

- `buy(hrid, lv)`：按「购买方式」取价；`sell(hrid, lv) = floor(按「出售方式」取的价 × (1 - MARKET_TAX_RATE))`；
- 有效价判定：`> 0`（缺价哨兵 `-1` / `0` 无效）；价格取自市场行 `a`（左一）/ `b`（右一）/ `p`（最近成交）。

| 选择 | 买入价                                                                                    | 卖出价                                                                      |
| ---- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 左一 | 取左一价 `a`；无效时回退 `p` → 官方指导价                                                 | 取左一价 `a`；无效时回退 `p` → 官方指导价                                   |
| 右一 | 取右一价 `b`；无效时回退 `p` → 官方指导价                                                 | 取右一价 `b`；无效时回退 `p` → 官方指导价                                   |
| 自动 | **取 `a`、`b` 中较低的可用者**（用户答复：取成本最低的一侧）；无效时回退 `p` → 官方指导价 | **取 `a`、`b` 中较高的可用者**（卖出到手最高）；无效时回退 `p` → 官方指导价 |

说明：手选的「左一 / 右一」只在指定侧无价时才走回落链（回落链结果仍按该侧口径使用）；「自动」在 `a`、`b` 间取对用户最有利的一侧。任一物品最终仍无有效价 → 相关获取方式不存在（§4.7）。

### 4.3 获取方式与成本（全部 100% 确定，无概率）

每个 `(line, k)` 的获取成本 `acq(line, k)` 取下面四者中最低的一条；主件与垫子也各按 `acq` 递归获取：

| #   | 获取方式       | 条件                                          | 成本                                                                       | 结果（得到的东西） |
| --- | -------------- | --------------------------------------------- | -------------------------------------------------------------------------- | ------------------ |
| 1   | 市场买成品     | 该物品该等级有买入价                          | `buy(line, k)`                                                             | `(line, k)`        |
| 2   | 镜子合成       | k ≥ 1，主件与垫子的获取成本可用，镜子有买入价 | `acq(line, k-1) + acq(B, max(0, k-2)) + buy(镜子, 0)`                      | `(line, k)`        |
| 3   | 买普通版精炼   | 有精炼线、碎片有买入价                        | `acq(B, k) + 碎片数量 × buy(碎片, 0)`                                      | `(R, k)`           |
| 4   | 买精炼版解精炼 | 有精炼线、精炼版获取成本可用                  | `acq(R, k) - 返还碎片数量 × sell(碎片, 0)`（返还数量取官方 `shardReturn`） | `(B, k)`           |

补充规则：

- **垫子永远是普通版**：游戏 `getPhilosophersMirrorCost(item)` 固定取 `baseItemHrids[0]`，即合成精炼版时消耗的也是普通版垫子，所以 `acq(R, k)` 的垫子同样取 `acq(B, max(0, k-2))`（这与 fastsim 允许精炼垫子的写法不同，我们按游戏源码收紧）。
- **合成公式的等级**：`+k` 由「`+(k-1)` 主件 + `max(0, k-2)` 普通版垫子 + 贤者之镜」做出；`k = 1` 时主件与垫子都是 `+0`（源码里垫子等级是 `max(0, 当前等级-1)`），所以 `+1` 也能自己做（fastsim 的 `n < 2` 守卫不允许，按游戏源码我们对齐）。
- **精炼材料按工匠茶生效折算**（2026-10-16 用户答复：工匠茶默认就是生效）：碎片数量 = 官方 `inputItems` 数量 × (1 − 工匠值)，工匠值取自游戏数据里 `/items/artisan_tea` 的 artisan buff（`flatBoost: 0.1`，即 100 → 90、300 → 270）。fastsim 用固定的 0.89（里面还含住宅等其他来源的减免），我们按游戏数据里的茶取值。
- **解精炼返还的是固定值**：`shardReturn` 是物品详情里的字段（100 → 50、300 → 150），不随工匠茶变化（解精炼是炼金动作，工匠茶只减免生产动作的材料）。
- **解精炼必定成功且在等级内往返**：源码 `AlchemyUnrefineSuccessRate = 1`，输出 `unrefineDetail.baseItemHrid` 且保留强化等级；金币手续费 `floor(5 × (10 + 等级))`（几百金币）忽略不计。
- **本模型不卖出任何中间件**：路线里只有「买到手」与「改造手上的东西」，因此不存在把买卖价差当作收益的步骤。

### 4.4 求解：按等级从小到大递推 + 四种方案

**第一步：逐级递推获取成本**（`buildAcquisition`）

- 等级 `k` 从 0 递增到 20，每一级里先算普通线、再算精炼线、最后用精炼线回头改进普通线：
  1. `acq(B, k) = min( 市场买 B@k, 镜子合成 B@k )`；
  2. `acq(R, k) = min( 市场买 R@k, 镜子合成 R@k, acq(B, k) + 精炼材料 )`；
  3. 若 `acq(R, k)` 不是「精炼」来的，再试 `acq(B, k) = min( acq(B, k), acq(R, k) - 解精炼返还 )`。
- 为什么这三步一遍就够：镜子合成只用更低的等级（`k-1`、`k-2`，已在前面算完）；同一等级内「精炼 → 解精炼」这种来回操作必然变贵（材料按买入价、返还按卖出价且只有一半），所以第 3 步只从「买/合成来的精炼版」出发，不会出现两条线互相引用成环。

**第二步：列出四种方案并取最便宜的**（已有装备的去处）

| 方案                 | 条件                                               | 花费                                                             | 说明                                     |
| -------------------- | -------------------------------------------------- | ---------------------------------------------------------------- | ---------------------------------------- |
| 直接买成品           | 目标有买入价                                       | `buy(Lt, t) - 已有装备到手价`                                    | 卖掉已有装备（没选就是 0）再买成品       |
| 自己做               | `acq(Lt, t)` 可用                                  | `acq(Lt, t) - 已有装备到手价`                                    | 卖掉已有装备，从零按最便宜获取路线做出来 |
| 用已有装备当主件升级 | 已有装备是目标物品本身或它的普通版（选择时已约束） | `Σ(垫子 + 镜子)`（目标为精炼版时末尾精炼）                       | 一路用它当主件往上做，不使用也不卖掉它   |
| 用已有装备当垫子     | `t ≥ b + 2` 且目标有可获取的主件                   | `它升到 +m 的花费 + 买主件 + 镜子 + 继续升到目标`（对 m 取最低） | 已有装备（精炼版先解精炼）当垫子用掉     |

- 四个方案**全部列在界面的「全部方案」表里**并标出最佳（不可用的方案也列出，说明原因：市场没有这个等级 / 缺价，不可用）；没有选已有装备时只有前两条。
- 「已有装备到手价」有两种卖法：**直接卖**（精炼版就卖整件）与**解精炼后卖普通版 + 卖回碎片**；不用它的两条方案会把两种都试一遍取更便宜的那种（§4.4 的碎片净额结算），汇总里的「直接买成品」用按卖价更值钱的那条。
- 「用已有装备当垫子」里 `m` 从已有等级取到 `t - 2`：`m = b` 就是「直接拿手上的当垫子」，`m > b` 是「先把手上的升到 +m 再当垫子」。两种情形用掉的镜子数固定为 `t - b - 1`。
- **方案内碎片净额结算**（2026-10-16 用户反馈修正）：一件装备的精炼与解精炼用的是同一种碎片，所以整条方案合起来算一次——解精炼拿回的碎片先顶掉后面精炼要用的量（按买入价，等于省下这笔买入），多出来的才按卖出价折钱。旧算法把返还按卖出价折钱、又全额买回精炼材料，会把「拿回 150 个碎片、又买 300 个」重复计价（用户原话：难道不是买 150 就够了吗）。
- 总花费 = 四个方案里净花费最低的那个；最优路线 = 该方案的步骤序列（`起点 / 卖掉已有装备 / 买入 / 合成 / 精炼 / 解精炼`）。步骤花费的合计严格等于总花费：垫子按独立步骤计价、合成步骤只计贤者之镜的价格、解精炼的返还与后续精炼按净额结算。
- 全部方案都不可用（目标、镜子或关键等级全缺价）时按 §4.7 提示缺价，不显示 0 花费。

**为什么不做「卖出换购」的中间步**（2026-10-16 修正的核心）：在「自动 = 买入取低价侧、卖出取高价侧」口径下，只要某等级的左一价 × 0.96 高于右一价（真实快照里大量存在，如 `acrobatic_hood` +12：左一 1020M、右一 940M），「买入再卖出」本身就净赚，路线会退化成一串纯换手步骤（旧模型 +6 → +13 的路线就是「买 +8 → 卖 +8 → 买 +10 → 卖 +10 → 买 +12 → 卖 +12 → 合成」，凭空「省」了几千万）。用「不卖中间件 + 方案比较」代替它之后，这类幻影收益不会出现；如果某等级的市场价倒挂到能靠买卖赚钱，那是套利机会而不是升级计划，不该进本计算器。

### 4.5 逐级对比数据（回答「每一级最划算的方案」）

逐行列出从「已有装备等级 + 1」（没选已有装备时从 +1）到目标等级，每级给出目标线的四列（外加最优路线标注）：

| 列           | 含义                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| 等级         | 目标线上的 `+k`                                                                                       |
| 市场买价     | 按当前购买方式直接买 `(Lt, k)` 的花费；市场没人挂这个等级时为空                                       |
| 最低获取成本 | `acq(Lt, k)`；比市场买价低时标绿                                                                      |
| 获取方式     | 该成本来自哪里：市场买 / 镜子合成（附垫子等级）/ 买普通版精炼 / 买精炼版解精炼                        |
| 最优路线     | 最优路线在该等级实际做的事：合成 / 买入 / 精炼 / 解精炼（不在目标线上时注明版本），未用到为「未采用」 |

### 4.6 示例演算（用 `references/game-data/marketplace.json` 的真实数据）

自动口径 = 买入取 `min(a, b)`、卖出取 `max(a, b) × 0.96`；`acrobatic_hood` 快照：+6 `a=81M / b=73.4M`，+7 `90.2M`（买入价），+11 `558M`，+12 `940M`，精炼版 +12 `1.1B`，镜子 `640M`（买入价）。

- **普通 +6 → 普通 +7**（已有装备 = 普通 +6）：直接买 = 90.2M − 卖掉 +6 到手 77.76M = **12.44M**；自己做（`acq(+7)`）= 90.2M − 77.76M = 12.44M；用已有装备当主件（+6 + 垫子 +5 68.8M + 镜子 640M）= 708.8M。最优 = 12.44M（卖掉已有装备直接买）。
- **普通 +11 → ★+13**（已有装备 = 普通 +11，无 ★+13 挂单）：直接买不可用；自己做 = `acq(★+13) = acq(★+12) 1.1B + 普通 +11 垫子 558M + 镜子 640M = 2.298B`，减掉卖掉 +11 到手 535.68M = **1.762B**；用已有装备当主件 = 2.316B；用已有装备当垫子 = 买 ★+12 1.1B + 镜子 640M = **1.740B**（手上的 +11 直接当垫子）。最优 = 1.740B。
- **精炼与解精炼**（测试固定数据）：普通 +13 自制 1770M + 90 个碎片（工匠茶折算）176.4M = 1946.4M < 直接买 ★+13 2000M，逐级表 +13 行标绿、获取方式「买普通版精炼」；普通 +2 自制（2 个 +0 垫子 + 2 个镜子 = 2300）不如「买 ★+2 解精炼」（3000M − 50 × 48M = 600M），获取方式显示「买精炼版解精炼」。
- **碎片净额结算**（测试固定数据）：已有装备 ★+0、目标 ★+1、碎片买价 50 / 卖价 48 —— 路线「解精炼 ★+0（拿回 50 个碎片，留着精炼用）→ 卖普通 +0（96）→ 买普通 +1（100）→ 精炼 90 个里只买 40 个（2000）」= 2004；旧算法会把 50 个按卖出价折 2400、再全额买 90 个 4500，多算 100（= 50 × 买卖价差 2）。

### 4.7 边界与异常处理

| 场景                                  | 处理                                                                                                              |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 没有选择目标装备                      | 结果区只显示「请选择目标装备」，不做任何计算（目标是必选项）                                                      |
| 已有装备不是目标物品或它的普通版      | 选择面板里根本不会出现（只有「无 / 它的普通版 / 目标物品本身」三项，按游戏物品顺序），计算器也会按 `invalid` 拒绝 |
| 已有装备的等级高于目标等级            | 等级下拉只列到目标等级；计算器按 `invalid` 拒绝并提示                                                             |
| 已有装备 = 目标物品且等级相同         | 允许：最优方案是「用已有装备当主件升级」，总花费 0（本来就有）                                                    |
| 已有装备 = 精炼物品且没有解精炼数据   | 「解精炼」相关做法不可用（当垫子、解精炼后卖），其余方案照常                                                      |
| 某物品 / 某等级缺价                   | 涉及它的获取方式不存在；某等级连普通版都获取不到时，更高等级与目标都不可达                                        |
| 已有装备自身无卖价                    | 不阻断：不用它的做法按不抵扣计算（相当于留着旧装备），界面注明                                                    |
| 镜子缺价                              | 所有合成方式不存在；仍可比直接买成品、精炼、解精炼（若有价）                                                      |
| 碎片缺价（目标为精炼）                | 精炼方式不存在；解精炼的返还按碎片卖出价计，碎片无卖价时该项按 0 返还（不作为更优项）                             |
| 目标成品缺价且无获取路径              | 汇总区提示「无法用必成路线到达」与缺价清单（镜子、目标、递推里第一个断掉的等级、碎片）                            |
| 物品不可强化（无 `enhancementCosts`） | 不进入目标选择器（只列出 532 件可强化装备）                                                                       |
| 目标已到 +20                          | 等级下拉照常列到 +20；已有装备等级跟着目标是上限，能算多少算多少                                                  |
| 买卖价差倒挂（卖价高于买价）          | 模型里不卖中间件，因此不产生套利步骤；倒挂只影响「卖掉已有装备」这一次抵扣的价值                                  |

### 5.2 装备选择器（复用装备提升计算器的交互形态）

- 选择区与装备提升计算器逐项一致：滚动容器 + `max-content` 网格居中，选择器 10.5rem / 间距 0.35rem，标题加粗居中，卡片内「强化等级」文字按同一做法视觉隐藏（只留下拉）；购买方式 / 出售方式用同款「加粗居中标题 + 下拉」排布；
- 目标装备（第一个选择器、必选）：点击卡片打开选择面板 —— 顶部「部位类型过滤 + 搜索框」，下方是物品卡片网格（图标 + 名称 + Lv.），只列出可强化装备（532 件）；**卡片顺序 = 游戏的物品顺序**（`itemDetailMap.sortIndex` 升序，游戏里的物品列表就是这个顺序；同序号时再按等级与名称）；
- 类型下拉顺序取自游戏 `equipmentTypeDetailMap` 的 `sortIndex`（双手 / 主手 / 副手 / 背部 / … / 饰品），生活工具（`*_tool`）合并成一项「工具」放在最后；
- 已有装备（第二个选择器、可选）：点击卡片打开同一套面板，但没有筛选行，只有「无 / 它的普通版 / 目标物品本身」卡片（目标本身是普通版时只有两张），**顺序同样是游戏的物品顺序**（`itemDetailMap.sortIndex` 升序，普通版在精炼版之前，与目标面板的卡片一致），卡片左上角标注「基础版 / 精炼版」；选「无」表示不用已有装备；
- 两侧各带强化等级下拉：目标侧 `+0..+20`，已有侧 `+0..目标等级`（没选已有装备时不显示等级下拉）；
- 选择变化即重算；计算是同步的纯函数，不需要防抖。

### 5.3 交互与提示

- 所有金额用工程现有格式化口径；操作序列里的物品名带「+等级」和「★」，贤者之镜本身没有强化等级、只写名称与数量；
- 路线步骤：卖掉已有装备与解精炼返还都是负花费（绿色边框标出），起点步骤不显示花费；解精炼步骤注明返还的碎片里有多少留作后面的精炼、多少卖出，精炼步骤在括号里注明有多少碎片是解精炼拿回的（花费只算实际要买的量）；
- 「全部方案」表：四个方案按固定顺序（直接买 / 自己做 / 当主件 / 当垫子）列出，最佳方案整行标绿并在「说明」列写「最佳」；不可用的方案花费列写「—」并说明原因；
- 逐级表的「最低获取成本」比市场买价低时用绿色标出；「获取方式」列写明来源，镜子合成补上垫子等级；
- 选择面板打开时弹窗至少撑到能容纳 **4 行物品卡片**（6rem 卡片 + 间距 + 筛选行 + 关闭按钮 + 内边距 ≈ 31rem），列表再长时面板内部滚动；
- 缺价、不可达时在对应位置用弱化文字说明，不弹 toast；
- 市场数据来源与更新时间提示行复用市场服务的时间文案。

### 7.2 计算逻辑复核（2026-10-16，用户答复：参考 mwi-fastsim 的装备获取成本）

- 每个等级的获取成本按等级递推（市场买 / 镜子合成 / 买普通版精炼 / 买精炼版解精炼，垫子与主件同样递归取最便宜）；

- 路线里不卖任何中间件，也没有负花费的换手套利步；
- 新增解精炼（拿回一半碎片，`shardReturn` 取自游戏数据）；
- 逐级表改成「市场买价 / 最低获取成本 / 获取方式 / 最优路线」。

与 fastsim 的三处取舍：垫子只允许普通版（游戏源码 `baseItemHrids[0]`）、`+1` 允许自己做（游戏源码 `max(0, 等级-1)`）、不加工匠 0.89 材料系数（MST 不读玩家 buff）。

## 八、明确不做 / 暂缓

- **不做**：普通强化（含失败概率与期望建模）、贤者之镜以外的保护物品（保护之镜、专属保护品、物品自身作保护）、成功率加成、福气茶（成功 +2）、强化耗时与喝茶成本、炼金转化（transmute）与分解（decompose）、解精炼的金币手续费（`floor(5 × (10 + 等级))`，几百金币）、工匠茶以外的工匠来源（住宅等，只按茶取值）、牛铃袋等特殊税率、跨物品换装（已有装备不再是目标物品或它的普通版）；
- **暂缓**：把「先把手上的升到 +m 再当垫子」单独做成可选行（当前由「用已有装备当垫子」方案内部对 m 取最低，路线里会写明）；展开某个方案看它的步骤（当前只展开最佳方案的步骤，其它方案给花费与次数）；工匠茶的开关（用户定为默认生效，暂不提供关闭）；
- **记录备查（低风险假设）**：精炼物品合成失败/降级在模型外（必成模型不涉及）；若后续游戏更新加入新的合成保护手段或改变税率，改 `constants.js` 与本文档对应小节即可。
