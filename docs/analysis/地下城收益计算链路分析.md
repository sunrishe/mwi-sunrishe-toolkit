# 地下城收益计算链路分析

本文档记录 MST 地下城收益计算器的最终业务口径、数据来源、期望算法和价格方向。计算器覆盖奇幻、阴森、秘法、海盗四个地下城及 T0-T2 难度。

## 1. 计算结论

计算器不模拟某一把战斗或某一次开箱，而是计算 24 小时的长期期望：

```text
地下城、难度、队伍人数、单次耗时、可选每日药品/饮料成本
→ 每日轮次
→ 普通/精炼宝箱期望（按官方公式随队伍人数缩放）
→ 递归展开宝箱内物品期望
→ 按 bid/ask 计算税后卖出收益
→ 分别扣除制作/购买门票与宝箱钥匙成本
→ 扣除每日药品/饮料成本
→ 每日期望收益
→ 每车期望收益
```

同一组输入和市场价格始终得到相同结果。

## 2. 用户输入

界面保留以下基础参数：

- 地下城。
- 难度 T0-T2。
- 队伍人数，选项 1-5，默认 5。
- 单次耗时，单位为分钟，必须大于 `0`。
- 每日药品/饮料成本，单位为 `M`，可留空。
- 是否使用工匠茶；默认勾选。
- 是否使用暴饮之囊及其强化等级；在当前装备、背包和仓库的全部持有物品中选择最高强化等级，拥有时自动勾选，没有时不勾选。
- 是否让披风不计算收益；默认不勾选。勾选后，所有 `equipmentDetail.type` 为 `/equipment_types/back` 的宝箱产物按 `0` 估值。
- 是否让牛铃不计算收益；默认不勾选。勾选后，牛铃（`/items/cowbell`）与牛铃袋（`/items/bag_of_10_cowbells`）在计算路径中的单价按 `0` 计：牛铃价格由牛铃袋折算而来，牛铃袋本身就是 10 个牛铃，两者同属牛铃收益。
- 是否启用自定义模式；默认关闭。

启用自定义模式后额外显示：

- 钥匙来源：制作钥匙或购买钥匙。
- 钥匙材料/成品购买方式：左买（`ask`）或右买（`bid`）。
- 货物出售方式：左卖（`ask`）或右卖（`bid`）。

战斗掉落数量（Combat Drop Quantity）固定按 `0.295`（29.5%）处理，战斗掉落率（Combat Drop Rate）、统计周期和市场税开关均不参与本计算器，不提供对应输入。每日固定按 24 小时计算，卖出收入固定扣除 5% 市场税（牛铃袋按 18% 特殊税率）。

首次打开默认选择按官方 `sortIndex` 排序后的第一个地下城、T0、5 人队伍和 30 分钟单次耗时。

## 3. 每日轮次与宝箱数量

### 3.1 每日轮次

```text
每日轮次 = 24 × 60 ÷ 单次耗时
```

例如单次耗时为 14 分钟：

```text
1440 ÷ 14 = 102.857142857... 车/日
```

每日轮次在计算链路中保留完整精度，不向下取整；界面展示时最多保留两位小数。

### 3.2 宝箱数量公式

普通宝箱数量按官方 Wiki 公式计算，战斗掉落数量固定为 `0.295`：

```text
Chests = 5 / Party Size × (1 + Combat Drop Quantity)
每车普通宝箱 = 5 ÷ 队伍人数 × 1.295
```

队伍人数取 1-5 的整数，默认 5。各人数下每车普通宝箱期望：

| 队伍人数 | 计算          | 每车普通宝箱期望 |
| -------- | ------------- | ---------------- |
| 1        | `5/1 × 1.295` | `6.475`          |
| 2        | `5/2 × 1.295` | `3.2375`         |
| 3        | `5/3 × 1.295` | `2.15833…`       |
| 4        | `5/4 × 1.295` | `1.61875`        |
| 5        | `5/5 × 1.295` | `1.295`          |

默认 5 人时每车普通宝箱期望为 `1.295`，与历史口径一致；`1.295` 正是官方公式在“5 人 + 29.5% 战斗掉落数量”下的精确结果。精炼宝箱期望 = 普通宝箱期望 × 精炼系数：

| 难度 | 精炼系数 | 每车精炼宝箱期望（默认 5 人） |
| ---- | -------- | ----------------------------- |
| T0   | `0`      | `0`                           |
| T1   | `0.33`   | `1.295 × 0.33`                |
| T2   | `1`      | `1.295`                       |

单车和每日宝箱数量参与计算时均保留完整精度：

```text
每日普通宝箱 = 每日轮次 × 5 ÷ 队伍人数 × 1.295
每日 T0 精炼宝箱 = 0
每日 T1 精炼宝箱 = 每日轮次 × 5 ÷ 队伍人数 × 1.295 × 0.33
每日 T2 精炼宝箱 = 每日轮次 × 5 ÷ 队伍人数 × 1.295
```

默认 5 人、14 分钟时的展示结果为：

| 难度 | 每日轮次 | 每日普通宝箱 | 每日精炼宝箱 |
| ---- | -------- | ------------ | ------------ |
| T0   | `102.86` | `133.20`     | `0.00`       |
| T1   | `102.86` | `133.20`     | `43.96`      |
| T2   | `102.86` | `133.20`     | `133.20`     |

队伍人数只缩放宝箱数量基准，其他任何战斗掉落 Buff 不影响数量。

## 4. 宝箱内容期望

普通宝箱和精炼宝箱先按第 3 节得到数量，再读取游戏运行时 `openableLootDropMap`。每个掉落项使用：

```text
子物品期望数量 = 父宝箱期望数量 × dropRate × (minCount + maxCount) ÷ 2
```

处理规则：

1. 相同物品在同一宝箱、不同宝箱或不同递归路径中出现时合并。
2. 子物品仍是可开启宝箱时继续递归展开。
3. 每层可开启宝箱按其期望开启数量累计对应钥匙需求。
4. 使用递归路径集合防止异常循环掉落表无限展开。
5. 只给最终物品计价，不给宝箱写死单箱价值。

不可直接交易的地下城代币按 `shopItemDetailMap` 中可兑换商品的市场价值折算。

### 4.1 宝箱掉落物表格

结果区提供“收益结果”与“掉落物”两个页签，同时只显示一个表格。掉落物表就是**官方宝箱的掉落物列表**：普通宝箱与精炼宝箱各一小节（节头注明每日开箱数量），每小节直接列出该宝箱的掉落条目。同一物品的多条掉落（掉率或数量区间不同）分别成行。列包括物品、掉率、期望数量、左一总价和右一总价，各节标题行右侧展示该节价值小计，底部合计行只汇总左一/右一总价，小计与合计都不含期望数量。

“掉率”列单行展示该条目的官方生效掉率（`dropRate` 按难度修正），单元格悬浮提示展示官方掉落数量区间 `min-max`（`min == max` 时只显示数字）。掉率是“打开该宝箱”的掉率，不按每日两类宝箱总量换算，因此普通专属条目不受精炼宝箱稀释：例如官方海盗普通宝箱含两条 `pirate_essence` 掉落（`dropRate 1` × 400-800 与 `dropRate 0.05` × 2000-4000），T2 下仍显示 `100%` 与 `5%`，悬浮提示分别为 `掉落数量 400-800` 与 `掉落数量 2000-4000`。

“期望数量”等于该条目的每日期望产出数量，由每类宝箱单独计算：

```text
期望数量 = 每日该类宝箱数量 × 生效掉率 × 平均掉落数量 = 每日该类宝箱数量 × 生效掉率 × (min + max) ÷ 2
```

例如海盗普通宝箱 T0 每日 `1.295` 个：`1.295 × 100% × 600 = 777`。期望数量单元格带悬浮提示（虚线下划线），展示完整计算公式与结果：`期望数量 = 1.295 个普通宝箱 × 100% × (400+800)÷2` 换行后 `= 777`。

掉落表价格固定按市场 `bid`/`ask` 报价税前计算（不扣任何税），不随“收益扣除市场税”选项和钥匙来源变化；缺价处理与“披风不计算收益”“牛铃不计算收益”排除规则与预期产出区相同。宝箱条目（本身仍出现在开箱掉落物列表中的物品）按 `expandChestItems` 递归展开后的最终物品税前估值（如海盗普通宝箱掉落的 `large_treasure_chest` 按金币、牛铃与宝石等展开内容估值，不再显示 0），单行单价 = 单宝箱展开价值，总值 = 期望数量 × 单价。各节小计与合计行都等于本列表各行折算价值之和（`askTotal`、`bidTotal` 为各行累加，普通/精炼小计分别累加本小节），**不再**等于递归展开后的每日宝箱产出；小计与合计行只展示左一/右一总价。掉落表容器只保留横向滚动，纵向滚动由整个弹窗容器承担（单一滚动条）。金额使用 `formatCompactNumber` 最多保留两位小数（大数自动切换 K/M/B/T 后缀），掉率百分比最多两位小数，数量与结果表一致最多保留两位小数并去掉尾随 `0`。

## 5. 门票与钥匙成本

### 5.1 数量

```text
单车门票 = 每车普通宝箱期望（5 ÷ 队伍人数 × 1.295）
每日门票 = 每日普通宝箱期望
单车宝箱钥匙 = 单车需要开启的宝箱期望
每日宝箱钥匙 = 每日需要开启的宝箱期望
```

单车门票使用完整精度的普通宝箱期望，默认 5 人为 `1.295`。单车宝箱钥匙同样按完整精度的单车宝箱数量递归统计，例如默认 5 人、T2 为 `1.295 + 1.295 = 2.59`。每日门票和每日宝箱钥匙使用每日宝箱期望，因此 14 分钟时每日门票展示为 `133.20`，不等于每日轮次展示值 `102.86`。普通宝箱与精炼宝箱使用同一种官方开箱钥匙时，两者数量相加；嵌套宝箱另需钥匙时继续计入。

### 5.2 制作与购买成本

默认模式同时计算制作钥匙和购买钥匙两套结果。购买成本直接读取门票或钥匙的成品市场价；制作成本读取官方制作配方：

```text
单位原始材料成本 = Σ(材料数量 ÷ 配方产出数量 × 材料单价)
```

暴饮强化等级下拉框只由暴饮之囊复选框控制；计算制作成本时，只有同时使用工匠茶并勾选暴饮之囊才计算其饮品浓度：

```text
暴饮之囊饮品浓度 = 勾选 ? 基础值 + 强化等级 × 每级加成 : 0
工匠茶 Artisan = 工匠茶基础 Artisan × (1 + 暴饮之囊饮品浓度)
材料消耗倍率 = 1 - 工匠茶 Artisan
单位制作成本 = 单位原始材料成本 × 材料消耗倍率
```

工匠茶和暴饮之囊只影响制作成本，不影响购买成本。门票和宝箱钥匙在同一张表的“材料成本”区同时展示制作/购买的单位和每日成本，不展示每车成本或单独的材料消耗格子。

自定义模式复用这两套成本数据：选择制作钥匙时，买入档位作用于门票和开箱钥匙的制作材料；选择购买钥匙时，买入档位作用于门票和开箱钥匙成品。两种来源都会把所选档位分别应用到单位成本、每日门票成本和每日开箱钥匙成本。

可选的每日药品/饮料成本按输入值乘以 `1,000,000` 换算为金币，同时加入两套每日总成本。它不改变门票、钥匙或宝箱数量。

### 5.3 ask 与 bid

- `ask` 是当前最佳卖单价：立即购入时作为成本，挂单卖出时作为较乐观收入。
- `bid` 是当前最佳收购价：立即卖出时作为收入，挂单收购时作为较乐观成本。
- 保守列为 `bid` 卖出收入减 `ask` 购入成本。
- 乐观列为 `ask` 卖出收入减 `bid` 购入成本。
- 自定义结果不再绑定上述两组组合，购入侧和卖出侧分别使用用户选择的 `ask` 或 `bid`。

市场价格只接受正数。`ask` 缺失时，优先用有效 `bid` 反推未税前卖单价 `ceil(bid ÷ 0.95)`，再回退最近成交价；`bid` 缺失时不从 `ask` 反推，只回退最近成交价。全部缺价时按 `0` 估值并提示。

## 6. 税后收益

普通宝箱和精炼宝箱的内容分开汇总。所有可交易物品统一按 5% 市场税计算，牛铃袋按 18% 特殊税率计算：

```text
税后卖出单价 = floor(市场卖出单价 × 0.95)（牛铃袋为 floor(市场卖出单价 × 0.82)）
普通宝箱税后收入 = Σ(普通宝箱物品期望 × 税后单价)
精炼宝箱税后收入 = Σ(精炼宝箱物品期望 × 税后单价)

单个普通宝箱税后收益 = (普通宝箱税后收入 - 对应来源的门票成本 - 普通宝箱开箱钥匙成本) ÷ 每日普通宝箱数量
单个精炼宝箱税后收益 = (精炼宝箱税后收入 - 对应来源的精炼宝箱开箱钥匙成本) ÷ 每日精炼宝箱数量
```

金币不经过市场，不扣市场税。牛铃使用可交易的牛铃袋价格除以 10 估值，牛铃袋按 18% 特殊税率扣税。牛铃袋保留直接市场估值，不递归展开成牛铃（牛铃再按牛铃袋折算会形成估值环，缺价时会把两者都算成 0）；牛铃袋价格兜底顺序为挂单价 → 买价折算 → 最近成交 → 兜底价 `1075167`（官方 marketplace 快照 2026-08-15 最近成交价）估值，牛铃相应按 `107516.7` 折算，因此宝箱牛铃收益不会算成 0，也不计入缺价提示。

“披风不计算收益”只影响宝箱产出的背部装备估值。默认不勾选时，奇幻箭袋、阴森披风、秘法斗篷等背部装备仍按现有替代价格估值；勾选后这些背部装备的 `ask/bid` 单价都直接按 `0` 计算，不记为缺价。代币、金币和牛铃不受该开关影响。

“牛铃不计算收益”只影响宝箱产出的牛铃与牛铃袋估值。默认不勾选时，牛铃按其可交易的牛铃袋市场价 ÷ 10 估值；勾选后两者的 `ask/bid` 单价都直接按 `0` 计算，不记为缺价，也不影响门票、开箱钥匙等成本侧和其他物品。该开关同样作用于掉落物表的宝箱行展开估值（牛铃部分按 `0` 计入）。

最终收益为：

```text
每日期望收益 = 单个普通宝箱税后收益 × 每日普通宝箱数量
             + 单个精炼宝箱税后收益 × 每日精炼宝箱数量
             - 每日药品/饮料成本

每车期望收益 = 每日期望收益 ÷ 每日轮次
```

门票成本归入普通宝箱，精炼宝箱作为额外产出只扣自身开箱钥匙成本。普通和精炼宝箱的开箱钥匙按递归展开时的来源分别累计，避免跨宝箱类型分摊错误。宝箱收益行显示单箱收益，数量列仍显示每日宝箱期望；每日期望收益使用未显示舍入的单箱值乘每日数量汇总。T0 不展示精炼宝箱收益行。默认模式按制作/购买钥匙各自的保守与乐观结果形成四列；自定义模式左侧保留所选钥匙来源的两列区间，右侧两列合并显示用户所选买入和卖出档位的精确结果。不重复展示 3、7、14 天结果。每日轮次、门票、普通宝箱、可选精炼宝箱和市场数据时间保持同一行。数量和金额最多显示两位小数，并去掉小数末尾的 `0`。

## 7. 数据来源与边界

运行时数据来源：

- `actionDetailMap`：地下城、门票和制作配方。
- `itemDetailMap`：宝箱钥匙、工匠茶和暴饮之囊属性。
- `openableLootDropMap`：宝箱与嵌套宝箱的掉落表。
- `shopItemDetailMap`：不可交易代币的兑换价值。
- 游戏公开市场数据：当前 `ask`、`bid` 和最近成交价。

`1.295` 是官方公式“5 人 + 29.5% 战斗掉落数量”下的精确期望，队伍人数由用户输入，战斗掉落数量固定为 `0.295`，不再从旧计算器或 Combat Buff 反推。`references/` 只用于测试与核对，运行时代码不依赖本地参考文件。

当前不计算地下城战斗过程，单次耗时仍需手动输入。结果是当前参数和市场价格下的确定性长期期望，不保证某次实际开箱接近期望，也不预测未来价格。

## 8. Playwright MCP 回归清单

会话操作和交付记录格式见 `docs/analysis/Playwright MCP 使用规范.md`。

- 只能使用 Playwright MCP 服务器的 `browser_*` 工具（在 MCP 服务列表中按“Playwright”关键字找到，前缀随客户端不同），不得用 `playwright-cli`、Browser plugin 或 Node REPL 代替。
